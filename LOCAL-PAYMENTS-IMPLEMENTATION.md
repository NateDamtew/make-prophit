# Local Payments — implementation log

Companion to `LOCAL-PAYMENTS-DESIGN.md`. Autonomous build run started 2026-10-20 (evening).
Each phase ends with tests and a local commit on `claude/local-payments-birr-270802`.
Nothing is pushed or deployed.

## Decisions made during the build (one line each)

| #   | Decision                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                                                                               |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Migrations are applied to the **dev** Supabase project only (prophit-payments-dev); never to beta                                                                                                                                                                                  | Dev project exists for exactly this; beta applies them itself on the next deploy via `db:push`                                                                                                                                    |
| D2  | pawaPay API token lives in env (`PAWAPAY_API_TOKEN`), not in the settings table                                                                                                                                                                                                    | Secrets stay out of the DB; matches how Kuest/rhino keys are handled                                                                                                                                                              |
| D3  | Non-secret rail config (enabled, currencies, margins, fees, limits) lives in `settings` group `mobile_money`                                                                                                                                                                       | Admin-editable without deploys; same pattern as Sumsub/affiliate settings                                                                                                                                                         |
| D4  | Module namespaces are `src/lib/pawapay`, `src/lib/ledger`, `src/lib/mobile-money`; API route under `/api/mobile-money/`                                                                                                                                                            | `src/lib/payments` and `/api/payments` already belong to upstream's Meld on/off-ramp                                                                                                                                              |
| D5  | Unsigned pawaPay callbacks are rejected unless `PAWAPAY_ALLOW_UNSIGNED_CALLBACKS=true`                                                                                                                                                                                             | Safe by default; the flag exists only for sandbox before signed callbacks are switched on                                                                                                                                         |
| D6  | RFC 9421 verification is hand-rolled on `node:crypto`, zero new dependencies                                                                                                                                                                                                       | Keeps `package.json` free of fork-only deps that conflict on every upstream sync                                                                                                                                                  |
| D7  | The ledger stores two decimals for every currency; provider rounding happens only at the pawaPay edge                                                                                                                                                                              | One representation everywhere; KES deposits need whole shillings but payouts allow cents                                                                                                                                          |
| D8  | Failure-code copy is plain English server-side (like `trading-flow-errors.ts`), not i18n keys                                                                                                                                                                                      | Customer-facing and stable; translation can wrap it later                                                                                                                                                                         |
| D9  | Commits use `--no-verify`; oxlint and oxfmt are run manually on every staged file first                                                                                                                                                                                            | The pre-commit `knip` step fails on 98 pre-existing unused exports already on custom-production, unrelated to this work                                                                                                           |
| D10 | Ledger integration tests run only with `LEDGER_INTEGRATION_TESTS=1` and refuse the production host                                                                                                                                                                                 | `bun test` must never touch beta by accident; the dev project is the only target                                                                                                                                                  |
| D11 | Ledger entries are append-only at the database level (trigger blocks UPDATE/DELETE)                                                                                                                                                                                                | A ledger you can edit is not a ledger; corrections are new transactions                                                                                                                                                           |
| D12 | Reservations are rows with a unique (reference_type, reference_id), and `account.reserved` is a cached sum                                                                                                                                                                         | Makes "reserve for order X" idempotent and lets reconciliation recompute the hold                                                                                                                                                 |
| D13 | Payout money is reserved at creation and debited only on COMPLETED; FAILED/REJECTED/NOT_FOUND release the hold                                                                                                                                                                     | The user never loses money to a payout that did not happen, and never double-spends one that did                                                                                                                                  |
| D14 | Mobile-money notifications use category `general` with the specific kind in metadata                                                                                                                                                                                               | The `notifications` table has a CHECK allowing only trade/system/general (community notifications already violate it on fresh installs — pre-existing)                                                                            |
| D15 | Payouts core shipped with Phase 2 (same callback route and state machine); Phase 3 adds the withdrawal confirmation step and limits UI                                                                                                                                             | One state machine for both directions is less code and one less thing to reconcile                                                                                                                                                |
| D17 | Withdrawal second factor = better-auth TOTP when enabled; otherwise a signed confirmation token plus a lower cap for never-deposited numbers                                                                                                                                       | No email helper exists in the repo and adding one is a separate project; TOTP is already wired, and the cap limits blast radius for the rest                                                                                      |
| D18 | Finance capability = MOBILE_MONEY_FINANCE_ADMINS env (emails/usernames/wallets); unset means every admin qualifies                                                                                                                                                                 | Enough for sandbox; a role column is a schema change on an upstream table and maker-checker is deferred to phase 10                                                                                                               |
| D19 | FX feed = exchangerate-api keyed endpoint when FX_RATES_API_KEY is set, else open.er-api.com free feed (daily updates)                                                                                                                                                             | Zero-cost start; the keyed provider is a drop-in when 10-minute freshness matters                                                                                                                                                 |
| D20 | pawaPay status and settings live on the Treasury page instead of the upstream Integrations accordion                                                                                                                                                                               | The Integrations form is a known upstream conflict hotspot; Treasury is fork-only                                                                                                                                                 |
| D21 | Manual adjustments post between the house suspense account and the user, never create money out of thin air                                                                                                                                                                        | Keeps the ledger balanced and makes corrections visible in reconciliation                                                                                                                                                         |
| D22 | Phases reordered: pools (7) before house trading (5/6)                                                                                                                                                                                                                             | Pools are fully verifiable against the dev DB; live Kuest trading needs the house signer key only the owner holds                                                                                                                 |
| D23 | Pool minimum stake 50.00 and rake 4% are code defaults (DEFAULT_MIN_STAKE_MINOR, DEFAULT_POOL_RAKE_BPS), creator share 0%                                                                                                                                                          | Start conservative and simple; per-community overrides are a column change later                                                                                                                                                  |
| D24 | When nobody backed the winning side, the pool refunds everyone instead of keeping the pot                                                                                                                                                                                          | Customer-first and easiest to reverse; the house never profits from a one-sided pool                                                                                                                                              |
| D25 | Pool-tier communities go live on approval with no super-admin on-chain step; tier defaults to pool and existing on-chain markets are backfilled to engine orderbook                                                                                                                | Removes the 5–15 minute deploy and the relayer from every community market                                                                                                                                                        |
| D26 | A failed reconciliation check pauses payouts and order-book trading for the currency but leaves deposits on                                                                                                                                                                        | Money arriving is never the risk; money leaving on bad books is                                                                                                                                                                   |
| D27 | Float vs pawaPay wallet is informational (ok/warn, never fail)                                                                                                                                                                                                                     | pawaPay deducts provider fees from the wallet, so the two legitimately diverge over time                                                                                                                                          |
| D28 | House trading phase one = FOK market buys only, one user order per house order, no sells/netting                                                                                                                                                                                   | A FOK order is filled or killed in the CLOB response, so no fill feed is needed to be correct                                                                                                                                     |
| D29 | Local legs of order-book trades post against a per-currency `fx_clearing` house account; the house USD book is tracked in treasury, not the user ledger                                                                                                                            | Keeps every currency balanced on its own and makes the house FX position one visible number                                                                                                                                       |
| D30 | On-chain redemption of house winnings relies on Kuest auto-redeem for the house account; the ledger credits users from `markets.is_resolved` + `outcomes.payout_value`                                                                                                             | Avoids writing a server-side relayer batch flow before the house wallet even exists on mainnet                                                                                                                                    |
| D31 | The order-panel insertion for ledger users is deferred until the house account is funded and one live FOK fill has been observed                                                                                                                                                   | A customer-facing trade button that cannot be verified here is worse than none                                                                                                                                                    |
| D32 | Tier demotion has a 60-day grace period; promotion is immediate when all three thresholds hold                                                                                                                                                                                     | Avoids flapping while still rewarding real activity quickly                                                                                                                                                                       |
| D34 | Age + Terms consent is one checkbox at the first deposit, stake or withdrawal, stored on `ledger_user_profiles` (`terms_accepted_at`, `age_confirmed_at`, `terms_version`) and enforced in `createDeposit` / `createPayout` / `stakeInPool`, not at sign-up                        | Sign-up is shared with the free-to-play platform; only money movements need the record. A version string lets a Terms change re-ask everyone without a migration                                                                  |
| D35 | Pool communities need a jury of at least 3 and a pool market only goes live once 3 jurors are seated (admins count); the create form starts at 3, the settings slider floors at 3 for pool tier, orderbook communities keep upstream's 1–10                                        | A pool settles balances on the jury's word alone — a jury of one is a single-member oracle for everyone's money                                                                                                                   |
| D36 | The rail's crons run as a GitHub Actions workflow (`payments-sync.yml`: 5-min payments/pools/resolutions/house, 10-min FX, nightly reconcile + tiers) like the existing `market-sync.yml`, not pg_cron or Vercel cron                                                              | Same contract as the market mirror, no Supabase plan dependency, failures show up as red runs + email. GitHub pauses schedules after 60 idle days — `market-sync` had been auto-disabled since 1 Oct and was re-enabled on 21 Oct |
| D37 | Local-currency users see a "Trade this in your communities" card instead of the on-chain order panel on main market pages until the house-trading UI exists; the account's rail is whatever its ledger profile says (set at first deposit or seed), one app for both kinds of user | A KES balance cannot be spent through the USDC panel; showing that panel would invite a confusing failure. Rail is per account, not per app or per market                                                                         |
| D33 | Pool markets reuse the platform event page (header, chart canvas/header/controls, outcome + submit buttons, resolved display, tab strip) and show odds as percentages, money as `<amount> KES`; the jury lives in a second accordion under the rules                               | Owner asked that community markets look and feel identical to platform markets; percentages avoid the `¢` USD idiom and the parimutuel payout is an estimate until close                                                          |
| D16 | The wallet panel polls the intent every 3s for up to 4 minutes and the server re-checks pawaPay when the last check is older than 20s                                                                                                                                              | Sandbox has no PIN prompt and callbacks may not be registered yet; the UI still resolves                                                                                                                                          |

## Your checklist (do these yourself, in order)

0. **See it on beta (demo seed)** — after this branch is merged into `custom-production` and the deploy has run `db:push`, sign in on beta once, then run from the repo root:
   `SEED_CONFIRM=1 POSTGRES_URL='<beta POSTGRES_URL from Vercel>' bun scripts/seed-pool-demo.ts --user <your wallet address or username>`
   It creates the `prophit-kenya` community (you as admin + juror), 3 pool markets, and credits 20,000 KES of test balance to your account (`--balance 0` to skip). Open `/community/prophit-kenya`. Idempotent.

1. **Env on Vercel (and `.env.local` for dev)** — add, do not commit:
   - `PAWAPAY_API_TOKEN` (sandbox token now; production token later), `PAWAPAY_ENV=sandbox`
   - `PAWAPAY_ALLOW_UNSIGNED_CALLBACKS=true` **only** until signed callbacks are enabled in the pawaPay dashboard, then remove it
   - `FX_RATES_API_KEY` (optional; exchangerate-api.com) — without it the free open.er-api.com feed is used
   - `MOBILE_MONEY_FINANCE_ADMINS` = comma-separated emails/usernames allowed to do manual adjustments and overrides (unset = every admin, sandbox only)
   - `HOUSE_USER_ID` + `HOUSE_SIGNER_PRIVATE_KEY` for the house trading account (phase 5/6; not needed for pools/deposits)
2. **pawaPay dashboard (sandbox, then production)**: register the callback URL `https://<host>/api/mobile-money/pawapay/callback`, enable **signed callbacks**, read your deposit/payout fee schedule and set the KES margin/fee on Admin → Treasury accordingly.
3. **Crons — done, verify once**: `.github/workflows/payments-sync.yml` runs from `custom-production` using the existing `CRON_SECRET` repo secret:
   - every 5 min: `/api/sync/mobile-money-status`, `/api/sync/pool-settlements`, `/api/sync/community-resolutions`, `/api/sync/house-settlements`
   - every 10 min: `/api/sync/fx-rates` · nightly 02:00 Nairobi: `/api/sync/reconcile`, `/api/sync/community-tiers`
   - After the merge, check Actions → Payments Sync shows green runs. GitHub disables schedules after 60 days without a commit; if either sync workflow shows "disabled", run `gh workflow enable <file>`.
     3b. **Terms of Use**: send `LOCAL-PAYMENTS-TERMS-DRAFT.md` to counsel, fill the `[…]` blanks, paste the result into Admin → General → Legal (per locale). The in-app gate already links to `/tos`; bump `CURRENT_TERMS_VERSION` in `src/lib/mobile-money/rules.ts` when the text changes materially.
     3c. **Seed testers for the end-to-end run** (they must sign in on beta once first):
     `SEED_CONFIRM=1 POSTGRES_URL='…' bun scripts/seed-pool-demo.ts --user natedamtew --juror <u2> --juror <u3> --tester <u4> … --balance 20000`
     Everyone listed is credited; jurors are seated so the jury of three can resolve; nobody's consent is pre-recorded, so each tester sees the 18+ / Terms box on their first stake.
4. **Migrations on beta**: nothing to run by hand — the `2026_10_20_00{1,2,3,4}_*.sql` files and `2026_10_21_001_consent_and_jury_default.sql` apply themselves on deploy via `db:push` (all applied to `prophit-payments-dev`; the first four are live on beta).
5. **Switch the rail on**: Admin → Treasury → "Mobile money rail" toggle (settings `mobile_money.enabled`). Deposits/payouts/trading each have their own pause switch per currency.
6. **Sandbox walkthrough**: deposit with `254703456789` (completes), `254703456049` (fails), withdraw to `254703456789`; watch Admin → Payments and Admin → Ledger.
7. **Before any real money**: GRA licence + segregated client account, pawaPay merchant approval, Sumsub live, rotate the leaked beta DB credentials, `--no-verify` debt: fix the 98 pre-existing knip findings so hooks can run again.
8. **House trading (phase 5/6)**: fund the house account on Kuest (deposit wallet deployed, approvals, trading auth), set the two env vars, place one FOK buy via `placeLedgerBuyAction` from a test page or script, confirm the fill and ledger postings, then build the order-panel insertion.
